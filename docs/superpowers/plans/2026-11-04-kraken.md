# Kraken Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Kraken core (Sonar + Hallmark + Conductor + reaction relay), the stage room templates, the Storm fault toolkit and the shopfront demo app, so one chat request runs Spark → Sonar pre-flight → Charter → Forge → Storm → close on Switch.

**Architecture:** One Python service registers as a Switch agent and holds one `scope=all` SSE connection. Every inbound event goes to a dispatcher: Sonar extracts and checks claims, the Conductor advances per-request state from fixed markers and commands, and Hallmark (SQLite) stores everything. Stage rooms are created with `create_room_from_yaml` from templates in `templates/`; the stage agents themselves are Claude Code / Codex / OpenCode run by Switch Console.

**Tech Stack:** Python 3.12, httpx, pydantic v2, pyyaml, anthropic SDK, discord.py, aiohttp (relay endpoint), FastAPI + uvicorn (shopfront), pytest + pytest-asyncio + respx.

**Spec:** `docs/superpowers/specs/2026-11-04-kraken-design.md`

## Global Constraints

- Python 3.12; package name `kraken`; all code async where it touches the network.
- Switch protocol: SSE `GET /agents/{agent_id}/events?connection_id=…&scope=all&filter=all`; heartbeat `POST /agents/{agent_id}/connection/beat` every **2 s** with `{connection_id, cursor}` (TTL 6 s; 404/409 → reopen the stream); ops `POST /agents/{agent_id}/ops/{name}` with arguments unwrapped and header `X-Switch-Connection-Id`; plain message `POST /agents/{agent_id}/message` with `{room_id, content}`; all calls `Authorization: Bearer <api_key>`.
- Reuse one connection id across reconnects; resume with `Last-Event-ID`; on a `gap` frame call `read_context(room_id=…)` for the affected room.
- Switch task operations are not used.
- Sonar raises a conflict only when confidence ≥ `sonar.threshold` (default **0.75**) and both sides are citable.
- Storm loop cap `storm.max_rounds` default **3**.
- Prompt tags have the form `[K-<n>]`, `n` = request id.
- Agent outcome markers, each on its own line: `BID:`, `ACCEPTED`, `SURVIVED`, `FAILED`.
- Models: `claude-haiku-5-5` for the decision filter, `claude-sonnet-5-5` for extraction, aliasing, conflict judgement and bid judging.
- Secrets only from environment: `SWITCH_URL`, `SWITCH_AGENT_ID`, `SWITCH_API_KEY`, `ANTHROPIC_API_KEY`, `DISCORD_RELAY_TOKEN`, `KRAKEN_RELAY_SECRET`.
- Every commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Echo loops:** Kraken's own messages, and agents quoting a conflict, must never be extracted as new claims or parsed as commands → covered in Task 5 (`test_ignores_own_and_agent_quotes`).
2. **Replayed events after reconnect:** an event with a sequence already processed must have no effect → covered in Task 9 (`test_dispatch_is_idempotent_by_sequence`).
3. **Emoji variants:** 👍🏽, ✔️, ✅, a 👍 with a trailing variation selector or whitespace all mean approve → covered in Task 7 (`test_emoji_variants`).
4. **Stale reactions:** a reaction or emoji reply on a `[K-n]` prompt whose request already moved past that gate is ignored with a one-line receipt → covered in Task 8 (`test_stale_command_rejected`).
5. **Restart mid-request:** after a process restart, conflicts already raised are not raised again and requests resume in their stored state → covered in Task 4 (`test_state_survives_reopen`) and Task 6 (`test_dedupe_across_instances`).

### Task 8: Conductor state machine

**Files:**
- Create: `kraken/conductor/state.py`
- Test: `tests/test_state.py`

**Interfaces:**
- Consumes: `Request`, `Command`, `Config`
- Produces a **pure** transition function (no I/O):
  - `State = Literal["SPARK","PREFLIGHT","CHARTER","FORGE","STORM","CLOSED","RESOLVING"]`
  - `Signal(BaseModel)`: `kind: Literal["brief_posted","preflight_clear","preflight_conflicts","bid","bids_done","accepted","survived","failed","resolved","timeout"], data: dict = {}`
  - `Action(BaseModel)`: `kind: Literal["open_stage","post","ping_owner","publish_hallmark","close"], stage: str | None = None, room: Literal["origin","stage"] = "stage", text: str | None = None`
  - `def step(req: Request, cfg: Config, inp: Signal | Command) -> tuple[dict, list[Action]]` — returns field updates for `Ledger.update_request` and actions. Rules (gate = `cfg.autonomy[...]`):
    - SPARK + `brief_posted` → store brief; gate `brief` human → post prompt (👍/👎); auto → PREFLIGHT + action `post` "running Sonar pre-flight".
    - SPARK + approve → PREFLIGHT. SPARK + reject → stay, post reason to stage.
    - PREFLIGHT + `preflight_clear` → CHARTER + `open_stage("charter")`. PREFLIGHT + `preflight_conflicts` → stay, post each conflict.
    - CHARTER + `bid` → append to `bids`. CHARTER + `bids_done`/`timeout` → gate `pick` human → post prompt listing bids numbered 1..n with 1️⃣..; auto → winner = `data["judged_winner"]`, FORGE + `open_stage("forge")`.
    - CHARTER + pick `n`|name → winner, FORGE + `open_stage("forge")`. Unknown name or n out of range → stay, post error.
    - FORGE + `accepted` → gate `merge`; then `storm_mode == "skip"` → CLOSED + `close`, else STORM + `open_stage("storm")`.
